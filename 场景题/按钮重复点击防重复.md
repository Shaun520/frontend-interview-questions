# 前端面试官：按钮重复点击怎么防，然后我就挂了

> 防重复点击必考题的完整回答思路

---

## 一、为什么这是一道"入门必考题"

防重复点击是前端入门必考题。**只会说 disable，在面试官眼里等于没答**，稍微一深挖，当场就挂。

**踩坑典型回答（反面教材）：**
- "禁用按钮就行"；
- 追问 3 个场景直接蒙圈：
  - 接口还没返回，用户疯狂点，怎么保证只发一次请求？
  - 多个按钮全局请求，总不能一个个加禁用吧？
  - 接口报错、超时，怎么自动恢复可点击？

**本质问题：**
- 考的不是能不能禁用按钮，而是你有没有**请求封装、工程化全局控制**的思维；
- 很多前端干了两三年还在手动写 disabled、手动加定时器，代码又乱又难维护，一面试就露馅。

---

## 二、完整回答框架：三层方案

真正高手防重复点击，张口就是**三层方案**，一层比一层通用、工程化。

### 第 1 层：基础方案（禁用按钮）

- 点击后立刻设置 `disabled = true`，请求结束后恢复；
- **优点**：简单，适合单按钮简单场景；
- **缺点**：复用性极差、代码冗余，每个按钮都要写一遍。

### 第 2 层：进阶方案（防抖节流 + 请求锁）

- 用**防抖/节流**思路：短时间内的点击只执行一次；
- 用一个变量标记**是否正在请求**：请求中拦截点击，请求结束解锁；
- 用 **Promise 状态管理**统一控制请求状态；
- **优点**：比基础方案通用，能处理"接口未返回前多次点击只发一次"的场景；
- **局限**：仍需在每个需要的地方处理，尚未做到全局统一。

### 第 3 层：高级方案（全局拦截器 + 自定义指令 + 幂等）

- **全局请求拦截器统一控制**：所有接口自动防重复，不用每个按钮写一遍；
- **自定义指令封装**：一行搞定，如 `v-preventReclick`；
- **接口防抖 + 幂等设计**：前端加后端双保险，彻底杜绝重复提交。

> 三层递进的核心是：从"单点禁用"走向"全局工程化控制"。

---

## 三、一句话总结

> 这道题考的不是你会不会禁用按钮，而是你有没有把防重复点击做成**全局请求层能力**的工程化思维。

- **普通开发**：只会手动 disabled + 定时器，代码乱、难维护、面试露馅；
- **高手**：张口就是三层方案——基础禁用 → 防抖节流 + 请求锁 → 全局拦截器 + 自定义指令 + 幂等设计，前端后端双保险。

**回答主线（背下来就能讲）：**
点击即禁用（基础）→ 变量请求锁 + 防抖节流 + Promise 统一状态（进阶）→ 全局请求拦截器 + v-preventReclick 自定义指令 + 接口幂等前后端双保险（高级）。
