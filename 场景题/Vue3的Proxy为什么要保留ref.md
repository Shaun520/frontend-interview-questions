# 前端面试官：Vue3 的 Proxy 能监听所有操作，为什么还要保留 ref？

> 一道把「ref / reactive 的设计取舍」讲透的 Vue3 面试必答题

## 一、完整回答框架：四层讲清 ref 的存在理由

视频从一个面试现场切入：

- 今天面了个 3 年前端，简历写着「精通 Vue3 响应式原理，源码都刷过两遍」；
- 我先问：Vue3 响应式和 Vue2 最大的区别是什么？
- 他脱口而出：**Vue2 用 Object.defineProperty，Vue3 用 Proxy——能监听数组下标、新增删除属性，没有拦截死角，性能还好**；
- 我点点头，直接开始灵魂追问：
  1. Proxy 既然能劫持对象的所有操作，为什么 Vue3 还要专门搞个 ref？
  2. ref 只是用来包数字、字符串这种基本类型的吧？
  3. 那包对象的时候，内部为什么还要自动转成 reactive？我直接全用 reactive 不行吗？
  4. 为什么把 reactive 对象解构出来就没响应式了？ref 解构就不会？
  5. 为什么模板里用 ref 不用写 .value，script 里就必须写？
- 面试到这就明白了：又是一个只会背 API 的，根本没搞懂 ref 和 reactive 各自存在的理由，怎么选都说不明白。

这道题考的不是 API 怎么用，而是你懂不懂**组合式 API 的设计逻辑**。别以为 ref 是补 Proxy 漏洞的凑数产物——它存在的原因有 **4 层**，一层比一层深。

### 第 1 层：Proxy 根本劫持不了基本类型

- 很多人吹 Proxy 无所不能，但别忘了：**Proxy 是专门给对象用的**；
- JS 里的数字、字符串、布尔值这些基本类型是**按值传递**的，不是对象；
- 你给一个数字 `1` 套 Proxy，根本没地方挂拦截逻辑，所以必须有一个容器；
- 把基本类型包成一个对象，这就是 ref 最朴素的作用；
- 它本质就是个带 `value` 属性的小对象，靠 get / set `value` 的时候触发依赖收集和更新；
- 但这只是最表面的原因，远不是全部。

### 第 2 层：ref 解决了 reactive 天生的两个致命缺陷

很多人说「基本类型用 ref、对象用 reactive 不就行了」——那为什么 ref 还要支持传对象？因为 reactive 从设计上就有两个绕不开的坑：

| 坑 | 说明 |
| --- | --- |
| 第一个坑：响应式随便丢 | `const { name } = reactive({ name: '张三' })`，解构出来的 name 直接没响应式；把 reactive 对象赋值给别的变量，或者当参数传进函数，引用一换，响应式直接断了。见过太多人写 hooks 返回 reactive，别人一解构拿了个死值，找 bug 找一下午 |
| 第二个坑：不能整体替换 | `let user = reactive({ name: '张三' })`，后面想直接 `user = { name: '李四' }` 替换整个对象，之前所有绑定这个 user 的地方全不更新了——因为你把整个 Proxy 对象给换了 |

而 ref 没这个问题：**它永远是个 ref 对象**，不管你解构还是传参，还是替换整个 `.value`，只要你访问 `.value`，响应式就一直在。

### 第 3 层：模板里不用写 .value，是编译器帮你干的活

- 很多人抬杠：ref 明明可以不用 `.value`，模板里写 `{{ count }}` 直接就能用，为什么 script 里非要写？
- 这根本不是 ref 本身的特性，是 **Vue 编译器偷偷给你干活**：编译模板的时候，自动把顶层的 ref 加上 `.value`；
- 而且这个自动解包是有坑的——**它只给顶层的 ref 解**：
  - 你要是写 `const state = { count: ref(0) }`，模板里直接写 `{{ state.count }}`；
  - 拿到的就是个 ref 对象，不会自动更新，多少人踩过这个坑。

### 第 4 层：ref 才是 Vue3 响应式的最小原子

- 很多人觉得 ref 是妥协的产物，其实搞反了：在设计定位上，**Vue3 的响应式系统里 ref 才是基础，reactive 反而是高层封装**；
- 你用 reactive 包对象的时候，内部访问到属性是 ref，会自动帮你解 `.value`；
- 而且 ref 的灵活性 reactive 根本比不了：
  - 大对象可以用 `shallowRef`，只跟踪 `.value` 的替换，不用做深层响应式，性能直接拉满；
  - 还可以用 `customRef` 自己定制依赖收集和触发，做防抖、缓存特别方便。

### 到底怎么选：记住三条就够了

| 场景 | 选择 | 理由 |
| --- | --- | --- |
| 基本类型 | `ref` | 数字、字符串、布尔，没得选 |
| 结构固定的复杂对象 | `reactive` | 比如表单数据、一组固定的状态，不会整体替换、不会解构丢失 |
| 抽离组合式函数 | `ref` | 返回 ref 永远不会出错，别人拿去解构也不会丢响应式；reactive 你返回出去，别人一解构就丢 |

---

## 二、一句话总结

> 这道题考的不是你背不背得出 Proxy 的缺点，而是你有没有真的在项目里踩过坑、懂不懂组合式 API 的设计逻辑。

- **普通开发**：天天喊 `.value` 反人类，写代码要么全用 reactive 到处丢响应式，要么全用 ref 写一堆冗余的 `.value`；
- **高级工程师**：知道什么时候该用什么，能写出别人拿去解构也不会出问题的 hooks——这才是真的把 Vue3 用明白了。

**回答主线（背下来就能讲）：**
Proxy 搞不定基本类型 → ref 兜住 reactive 的两个坑（解构丢响应式、不能整体替换）→ 模板不写 `.value` 是编译器的功劳（而且只解顶层）→ ref 是响应式最小原子（`shallowRef` / `customRef` 更灵活）→ 选型三条：基本类型用 ref、结构固定对象用 reactive、抽离 hooks 用 ref。
