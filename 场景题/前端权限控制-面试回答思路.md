# 前端面试官：说一下前端权限控制

> 一道把「中后台权限架构」讲透的进阶前端面试高频大题

## 一、完整回答框架：五层讲清权限控制

视频从一个面试现场切入：

- 今天面了个 4 年前端，面试官问：**你们项目里前端是怎么做权限控制的？完整流程和方案说说**；
- 候选人只简单提了「隐藏按钮、控制菜单」，追问权限流程、粒度划分、路由/按钮/接口多级管控、动态路由就答得前言不搭后语；
- 权限控制是中后台系统**核心必备能力**，也是高阶前端面试高频大题——只会表面用法根本算不上资深开发。

这道题看起来是背 API，实则是**权限架构设计**的核心。真正讲清楚的关键是五层递进——**整体流程 → 四层权限粒度（从大到小）→ 主流权限模型 → 常见问题优化 → 面试满分总结**。

### 第 1 层：整体流程（先把骨架搭起来）

```
① 用户登录 → 后端返回当前用户的「身份 / 角色 / 权限列表」
       │
② 前端存储权限数据（Pinia / Vuex / localStorage）
       │
③ 依据权限数据逐层控制：路由 → 菜单 → 页面按钮 → 接口请求
       │
④ 无权限时做拦截（隐藏 / 跳转 403 页面）
```

### 第 2 层：四大权限粒度（由大到小、逐层管控）

#### ① 路由权限（最高层级）

| 方案 | 做法 | 说明 |
| --- | --- | --- |
| **静态路由（传统）** | 提前写死路由表，登录后根据权限过滤移除无权限路由 | 简单但不够灵活 |
| **动态路由（主流）** | 前端只保留基础公共路由（登录页、404），登录后由后端返回**可访问路由**，前端用 `router.addRoute()` 动态添加 | 推荐方案 |
| **全局路由守卫** | `router.beforeEach` 判断当前用户是否有权限访问目标路由 | 非法访问直接重定向 403 |

#### ② 菜单权限

- 根据权限列表渲染侧边栏菜单；
- **直接隐藏无权限菜单**，做到菜单和路由**一一对应**；
- 从入口隔绝访问（点不到 ≠ 不能访问，但防君子）。

#### ③ 按钮 / 元素权限（页面级、最细粒度）

两种实现方式：

| 方式 | 代码 | 适用场景 |
| --- | --- | --- |
| **自定义指令 `v-permission`** | 全局注册 `directive('permission', { mounted: ... })` 判断当前元素是否在权限列表，无权限则移除 / 禁用 | 通用、复用性强 |
| **页面内变量判断** | `v-if="hasPermission('system:user:add')"` | 简单直接，适合一次性场景 |

#### ④ 接口权限（兜底防护，重中之重）

> **前端所有控制都是表层防护，可被绕过**——这是面试必说的金句！

- 在 axios 请求拦截器里校验权限，无权限直接拦截请求；
- **后端必须做二次鉴权**——这是最终安全防线，前端拦了也没用。

### 第 3 层：主流权限模型

| 模型 | 做法 | 适用 |
| --- | --- | --- |
| **RBAC（基于角色，项目通用）** | 用户 → 分配角色 → 角色绑定权限；一人可多角色 | 配置简单、易维护，**绝大多数后台系统都在用** |
| **ACL（细粒度、基于用户）** | 直接给用户分配独立权限，不经过角色 | 适合复杂个性化权限场景（比如某个 VIP 用户临时开个功能） |

90% 情况用 RBAC 就够了，ACL 是极端场景的补充。

### 第 4 层：常见问题与优化（加分项）

#### ① 刷新页面权限丢失

**原因**：动态路由 `addRoute()` 是内存操作，刷新就没了；Pinia 数据也会重置。

**解决方案**：
- 权限数据持久化到 localStorage；
- 路由守卫初始化时重新加载权限、动态追加路由。

#### ② 越权访问

**只靠前端隐藏没用**——手改 URL 就能直接进。

**多层兜底**：路由拦截 + 接口拦截 + **后端强制鉴权**。三层缺一不可。

#### ③ 权限更新实时生效

**角色变更后**：清空旧权限 → 重新请求权限列表 → 刷新路由与菜单。

#### ④ 权限标识规范

- 统一使用唯一权限标识（如 `system:user:add`），前后端约定一致；
- 别用中文做权限标识，后期维护会疯。

## 二、面试满分总结化数（背下来就能讲）

> **金句**：前端权限控制基于 **RBAC 角色模型**实现，分为**四层管控**——先登录获取角色与权限数据，通过**动态路由 + 全局守卫**控制页面访问权限；再根据权限渲染侧边菜单；再通过**自定义指令 `v-permission` 或 `v-if` 变量判断**控制页面按钮显隐；最后在请求拦截器做接口权限拦截。**前端仅做展示层控制，所有接口必须由后端二次鉴权**保障系统安全。

**回答主线：**
登录拿角色 + 权限 → Pinia/localStorage 持久化 → 动态路由 addRoute + beforeEach 守卫控页面访问 → 菜单权限对应过滤 → v-permission / v-if 控按钮 → axios 请求拦截 → **后端二次鉴权兜底** → 常见坑：刷新丢失要持久化重加载、越权要多层拦截、权限更新要清缓存重拉。
