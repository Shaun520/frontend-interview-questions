# 前端面试官：Vue3 组件通信方式有哪些？

> 一道把「组件通信选型」讲透的 Vue3 面试必答题

## 一、完整回答框架：四层划分通信方案

视频从一个面试现场切入：

- 今天面了个 4 年前端，简历写着「精通 Vue3，主导过好几个中后台项目」；
- 我先问：Vue3 里常用的组件通信方式有哪些？
- 他脱口而出：**父传子用 props，子传父用 emit，全局通信就用 Pinia**；
- 我点点头，追问了几个实际项目场景：
  1. 如果父组件要给曾孙组件传个用户信息，一层层往下传 props 太冗余，有什么更优雅的方案？
  2. 那 provide 传的值默认就是响应式的吗？怎么让后代组件能修改 provide 里的值？
  3. 跨两个完全没关系的兄弟组件怎么通信？
  4. 除了 Pinia 还有什么轻量方案？
  5. Vue3 里的 `$attrs` 和 Vue2 有什么区别？
  6. 为什么你用 ref 拿子组件实例经常拿不到值？
- 他越答越慌，最后直接沉默了。这就是 Vue 开发者最常见的问题——组件通信只会 props 和 Pinia，一到特殊场景就懵，连 API 的基本特性都没搞清楚。

这道题看起来简单，实则是 Vue 组件化的核心。**能把通信方式讲全，还能说清适用场景的 Vue3，才算真的用明白了。** 别什么鸡毛蒜皮的状态都往 Pinia 里塞——一个弹窗开关也存全局，最后 Store 乱成一锅粥。真正会用的前端会把组件通信分成 **4 层**来用：

### 第 1 层：父子直连，覆盖 80% 日常场景

这是最基础也是最高效的通信方式，**优先用，别上来就整全局状态**。

| 方式 | 方向 | 说明 |
| --- | --- | --- |
| `props` + `defineEmits` | 父 → 子 / 子 → 父 | 父传子声明类型和默认值；子传父 `defineEmits` 声明事件触发父组件方法。`v-model` 本质就是这个的语法糖，还支持一个组件绑多个 `v-model` |
| `ref` + `defineExpose` | 父 → 子（调用） | 父组件用 `ref` 拿子组件实例，直接调子组件的校验/重置方法。**注意：子组件必须用 `defineExpose` 把方法暴露出去**，不然你拿过去就是个空对象，啥也调不了 |
| `useAttrs` | 父 → 子（透传） | Vue3 里把 `$listeners` 合并进了 `$attrs`；父组件传的没在 `props` 里声明的属性、class、style、事件，全能通过 `useAttrs()` 拿到；做组件二次封装的时候直接透传就行，不用一个个声明 props |

### 第 2 层：跨代传值，告别 props 层层透传

- 就是 `provide` / `inject`；
- 祖先组件用 `provide` 提供值，不管多少层后代，直接用 `inject` 就能拿到；
- **别踩坑：默认传普通值不是响应式的**——必须用 `ref` 或 `reactive` 包裹后传，后代拿到才会跟着更新；
- 想让后代改值？**别直接传个对象让后代乱改，传一个修改函数下去**，保证数据流可控；
- 适合做全局主题、用户信息这种跨层级共享的数据。

### 第 3 层：全局 / 跨分支通信，无亲缘关系也能传

| 方式 | 说明 | 适用场景 |
| --- | --- | --- |
| `Pinia` | 官方推荐的全局状态管理，所有组件都能访问修改；有 devtools 追踪，数据流清晰 | 中大型项目的全局共享状态，比如用户信息、权限、全局配置；**小项目别滥用，徒增复杂度** |
| `mitt` | Vue3 移除了自带的 `$on / $off / $once`，装个 `mitt` 就能实现发布订阅，A 组件发事件、B 组件监听就行 | 小项目里简单的跨组件通知、给场景标记记事 |

> **`mitt` 两个坑**：一定要在组件卸载的时候 `off` 掉监听事件，不然会内存泄漏、事件触发越来越多次；也别滥用，不然事件飞得到处都是，出 bug 根本找不到在哪。

### 第 4 层：特殊场景，很多人写了三年都不知道

| 方式 | 说明 | 典型场景 |
| --- | --- | --- |
| **作用域插槽** | 别以为插槽只是传个内容——子组件可以把自己的数据通过插槽传给父组件，这本质是一种**子传父**的通信 | 封装表格组件，列表列的内容由父组件决定、数据由子组件传出来；很多人封装组件卡壳就是忘了这个 |
| **全局属性 `app.config.globalProperties`** | 在上面挂载的 `$utils`、`$axios` 等，所有组件里都能直接访问 | 挂全局通用方法，**别用来传频繁变的状态** |
| **路由传参** | 页面级组件之间传个 id / 状态，直接用路由 `query` / `params` 就行 | 不用让一大圈组件都存全局 |

## 二、一句话总结

> 这道题考的不是你能背出多少种 API，而是你有没有**组件解耦的思维**——能不能根据组件关系选最合适的方案。

- **新手**：上来不管什么场景都一把梭 Pinia，代码写得又冗余又难维护；
- **高级工程师**：父子通信优先 props → 跨代传值用 provide → 全局状态用 Pinia、简单通知用 mitt，选对了方案，组件才能既好复用又好维护。

**回答主线（背下来就能讲）：**
四层划分——父子直连（props + emit / ref + defineExpose / useAttrs）→ 跨代传值（provide + inject，别忘 ref 包裹才响应式、传函数别直接改）→ 全局跨分支（Pinia 管状态、mitt 管通知，别滥用）→ 特殊场景（作用域插槽 / globalProperties / 路由传参）。
